# SkladyX · обязательные правила для агентов

Перед любой задачей прочитать в указанном порядке:

1. `docs/ROSTAGRO_PRODUCT_SPEC.md` — утверждённое продуктовое поведение и источник истины.
2. `PROJECT_CONTEXT.md` — архитектура, tenant/security и факты о контурах.
3. `ROADMAP.md` — этапы и история доставки.
4. Перед staging/prod — `docs/OPERATIONS.md` и `docs/SERVER_INVENTORY.md`.

Обязательные правила:

- код и зелёные тесты не переопределяют продуктовую спецификацию;
- в задании и отчёте указывать ID затронутых правил спецификации;
- неоднозначность не закрывать предположением — остановиться и спросить владельца;
- новое решение владельца сначала внести в продуктовую спецификацию, затем реализовывать;
- остатки менять только через `src/lib/stock.ts` внутри транзакции;
- tenant, host, склад, роль, задача, резерв и скан проверяются сервером;
- текущую реализацию legacy нельзя использовать как образец нового продукта без явного правила;
- не менять и не удалять пользовательские данные, существующие миграции, секреты и серверные
  настройки без прямого разрешения;
- любое изменение: CI → staging → приёмка → отдельная команда prod;
- `ROSTAGRO_WORKFLOW_AUDIT.md` и `ROSTAGRO_MIGRATION_DESIGN.md` — исторические материалы,
  не источник актуальных требований.

Если задача конфликтует с `docs/ROSTAGRO_PRODUCT_SPEC.md`, остановить реализацию и показать
конфликт владельцу. Самостоятельно менять правило запрещено.
